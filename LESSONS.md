# Lessons

Bugs found, how they were found, and what changed. Interview material, so be specific.

| Date | Bug / surprise | How found | Fix |
|---|---|---|---|
| 2026-11-02 | A ThreadSanitizer binary aborted at startup with `FATAL: ThreadSanitizer: unexpected memory mapping`, before any of our code ran | First TSAN run under WSL2 (kernel with high `vm.mmap_rnd_bits`). TSAN reserves fixed shadow-memory ranges, and heavy ASLR can place libraries inside them | Locally: run TSAN binaries with ASLR off: `setarch x86_64 -R ctest --preset debug-tsan`. In CI: `sysctl vm.mmap_rnd_bits=28` |
| 2026-11-02 | The TSAN *build* failed even though compiling and linking worked | `gtest_discover_tests` runs the freshly linked test binary to list its tests, and that run hit the ASLR abort above | `DISCOVERY_MODE PRE_TEST`: discovery now happens inside `ctest`, which runs under `setarch -R` |
| 2026-11-02 | **Segfault at the end of every run on the real GPU** (Mesa D3D12 in WSL), never on llvmpipe and never under ASAN | Bisected the flags (driver, readback mode, clips), then a gdb backtrace: the crashing thread was the compositor thread *exiting*, inside `__nptl_deallocate_tsd`, jumping to an unmapped address | The D3D12 driver registers a thread-local destructor. `eglTerminate()` unloaded (dlclose) the driver before the thread exited, so glibc called into freed code. Fix: release the context and thread but don't terminate the display (`src/gfx/egl_context.cpp`) |
| 2026-11-02 | Release build failed with `-Warray-bounds` / `-Wstringop-overflow` inside `fmt::detail::bigint` | Inline chain showed {fmt} v9 internals pulled in by spdlog, a GCC 13 false positive | Rather than silence the warnings, the pipeline logs through a small `md/core/log.hpp` facade, so the {fmt} headers aren't compiled into that file |
| 2026-11-02 | The tracker saw ~74 "players" on a pitch with ~23 people | Dumped the detector's foreground masks (`--debug-dir`) and looked at them | Two causes: wet-turf sparkle under floodlights (fixed with a per-pixel deviation threshold + temporal AND) and **player shadows from four floodlights** (reduced with shape filters: min height, not wider than tall). Now ~42; shadows still leak (README *Limitations*) |
| 2026-11-02 | Live-mode latency was 666 ms p50 with 58 late frames per minute | Swept `--decode-threads` in `--realtime` mode | FFmpeg frame threading holds ~1 frame per thread: 4 threads → 185 ms, 8 → 345 ms, auto (~20) → 666 ms. `--realtime` now defaults to 4. Bonus: 8 threads gave *more* file-mode throughput (83 vs 70 fps), because auto oversubscribes the CPU alongside x264 |
| 2026-11-02 | Async PBO readback gave no speed-up | A/B run: 4.47 ms (async) vs 4.26 ms (sync) compositor p50 | Likely the D3D12-on-WSL driver synchronises on map. Kept as an option, reported honestly; worth re-testing on a native Linux GPU driver |
| 2026-11-02 | Stats reported 26 "dropped" audio packets in every run, independent of pool size | The count didn't change when the pool grew 4×, so it wasn't exhaustion | They were packets read after the requested end time, counted as drops. Fixed the counter (the stored 5-minute stats predate the fix) |
| 2026-11-02 | Two new director tests failed | Read the failure values | Both were **test** bugs: one checked the crop's left edge (which also moves when zooming) against a limit that applies to the centre; one assumed the camera froze mid-pan when tracks vanished. Fixed the tests, not the code |
